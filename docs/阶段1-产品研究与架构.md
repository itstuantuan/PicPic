# PicPic · 阶段 1 产品研究与架构

2026-11-26，待产品负责人确认。实施上限为阶段 5。本次交付研究、页面设计依据、系统边界和验收计划。沿用 PicPic 品牌和现有 Flutter 工程，iOS Bundle ID 与 Android applicationId 均为 com.poseguide.picpic。

## 产品研究与依据

| 已公开的 Empose 体验 | 对 PicPic 的决定 |
| --- | --- |
| 摄影师和被拍者都能在相机上看懂半透明人偶，选择动作后有三步指导和拍摄建议 | 保留 PicPic 的中央人偶和干净成片。详情先给完整动作，相机一次只提示一个最值得调整的动作 |
| 素材库覆盖站、坐、自拍、背影和双人，官方公布超过 160 款 | PicPic 的首发门槛为至少 100 个有区别的动作。每款绑定可校验的骨架，加入中文搜索与场景筛选 |
| 官方 FAQ 明确说明产品不检测或评分用户姿势 | 实时反馈是 PicPic 的新增研发项。手动拍照始终可用，低置信度时说明原因 |
| My Poses、场景推荐、Shoot Plans 和 Studio 分别解决参考图复用、现场选姿、整组拍摄和拍后编辑 | 创作归入 Create，拍摄计划从首页和个人页进入，成片可直接交给编辑器 |

研究范围为官网、公开产品资料、隐私说明和用户提供的相机截图。未登录实测 Empose 付费版。下述四 Tab、导航层级和布局是为 PicPic 设计的方案，未将其当作竞品内部实现。[官网与 FAQ](https://empose.app/) · [产品资料](https://empose.app/press/) · [数据处理说明](https://empose.app/privacy/)

## 现有工程与迁移

已有 24 个动作条目、透明 PNG、每款三步说明、真实相机、前后镜头切换、网格、倒计时、人偶手势、相册保存和模拟取景。相机初始化、切换与释放集中在 shoot_session.dart。main.dart 同时承担数据、状态、布局。已有图片可继续用于视觉引导；当前工程没有与这些 PNG 对应的目标关键点。当前 iOS 部署目标为 15.0，Android 延用 Flutter 工程的最低版本设置。依赖引入前先核对最低系统版本，特别验证用户现有的 iOS 15.8.8 真机。

阶段 1 的本地基线为 flutter analyze 无问题，flutter test 两项通过，覆盖切换姿势、居中、预览隐藏人偶，以及滚动选最后一款并查看下一步。当前未做双端硬件测试、姿态精度测试、云端或购买验证。迁移时先提取 catalog 与 theme，再接路由，最后替换相机外层入口。保留真实相机与示例模式的 VS Code 启动项。

## 页面与操作

| 页面 | 内容与可执行操作 | 返回或异常 |
| --- | --- | --- |
| Home | PicPic 字标、头像、设置、主图与开拍、推荐、热门、最近、场景入口、自定义姿势、计划入口 | 首次无历史时收起最近区。缺少全站热度时显示明确标记的编辑精选或本机常用 |
| Poses | 搜索、分类筛选、收藏筛选、排序、带图卡片。站、坐、自拍、背影、情侣、双人、行走、旅行、街拍、人像均可发现 | 无结果可清除条件；详情返回保留筛选及滚动位置 |
| Pose Detail | 人偶、三步动作、难度、人数、场景、镜头高度与拍摄建议；收藏、加入计划、开拍 | 携稳定 poseId 进入相机；双人卡标清 A/B |
| Live Camera | 全屏取景，人偶默认居中；移动、缩放、屏幕平面旋转、镜像、透明度、网格、切镜头、闪光、定时、快门、场景扫描和可选对齐提示 | 按设备能力显示控制；权限拒绝可去设置、重试或主动体验示例。扫描、推理故障不挡快门 |
| Preview | 查看原始成片，重拍、显式保存、分享或送入 Studio | 照片与姿势提示分层；编辑另存副本；返回可继续当前计划 |
| Create → 自定义 | 选参考图、识别一个人、预览骨架与轮廓、命名、保存、立即拍 | 多人时先选目标；未检出或遮挡过多时允许更换图片 |
| Create → Studio | 拍后进入或从相册选图，选风格、写描述、确认上传、查看任务、前后对比、保存及分享 | 支持排队、处理中、失败原因、重试、退出后查看历史和删除 |
| 场景推荐 | 相机快照或相册图 → 同意分析 → 环境标签与候选姿势 → 详情或直接拍 | 低置信度给手动选场景，区分手动与实际识别 |
| 双人拍摄 | 选双人动作 → 两套参考骨架 → 入镜分配 A/B → 分别提示 → 合影 | 一人离开只暂停该人的评分；两人交叉时必要时重新分配 |
| Shoot Plan | 建地点与主题、选多个姿势、按场景与站坐变化生成可调整顺序、开拍、绑定照片、完成、历史回看 | 重拍不重复计数；退出可续拍，删项后保持其余顺序 |
| Profile | 本机资料、收藏、最近、自定义、照片、AI 历史、计划历史、设置、隐私与用户协议入口 | 阶段 2–5 的本机资料明确标在当前设备；本机删除与云任务删除各自反馈 |
| 订阅页（阶段 6） | 对照免费与 Premium 权益、月付年付、符合条件的试用、恢复购买、订阅管理 | 价格/试用来自商店，服务端验证权益；阶段 5 不显示可购买的假套餐 |

主路径是 Home/Poses → 详情 → 相机 → 成片 → 保存、分享或 Studio。相机独立全屏，四个 Tab 各自保存导航状态。自定义姿势保存后出现在个人库，可走同一条拍摄路径。

延续当前街拍摄影、Georgia 风格 PicPic 字标、石墨色背景、珍珠灰人偶、白色快门和深色半透明胶囊。下面是阶段 2 的拟定设计值，便于跨页面复用。

## 内容生产与离线数据

目标用互斥的主类盘点 100 款，避免通过重复标签虚增数量。拟分站姿 22、坐姿 20、自拍 10、背影 8、行走 10、单人人像 10、情侣 10、朋友双人 10。旅行、街拍等作为多选场景或用途标签，可以跨主类筛选。先审现有 24 款，相近动作必须在受力脚、四肢布局、机位或双人配合上存在可拍出的区别；不能通过镜像换色充数。若全部通过还需 76 款，未通过项另行补齐。新素材记录创作来源与商业使用依据。

每条记录含稳定 ID、版本、标题/搜索词、人物数量、主类/标签、难度、适用场景、视角、拍摄建议、三步动作、缩略图、透明人偶、源画布尺寸、人偶占用区域及一至两套目标关节。收藏与使用次数属于用户状态。生产时在图上标注关节点，或由绑定骨骼的模型导出二维投影，再逐张校准。姿势库随包附缩略图、关键点与覆盖图，离线可搜可拍。历史与收藏用本地 SQLite；重启可恢复。远端同步另行接入。以内容清单检查缺图、重复 ID、双人缺第二骨架和骨架越界。

## 系统和数据流

| 层 | 选择与职责 |
| --- | --- |
| Flutter | Riverpod 管理目录、收藏、拍摄会话、识别结果与任务；GoRouter 管理四个分支、详情、独立全屏相机和深链。相机控制器仍由会话唯一持有 |
| iOS / Android | 保留 camera 插件原生预览和拍照；原型验证后在同一捕获会话旁路送帧给 Swift/Kotlin 的 MediaPipe Tasks。相机插件公开接口不足时做窄范围原生适配，避免启动第二个摄像头。原生侧只保留最新待处理帧，异步回传点位与置信度 |
| 本机库 | 版本化内容 manifest + SQLite + 私有文件目录，记录收藏、使用、计划、照片引用、已生成任务；保存到系统相册另走现有能力。开始使用计数在进入真实拍摄后每会话记一次，失败的保存可重试 |
| 云 AI | 阶段 5 单一服务端入口统一管理认证、模型、超时、配额、错误和重试。优先采用 Gemini 的图像理解和指令式照片编辑；模型 ID 在部署环境配置，上线前用目标账号验证可用性。OpenAI 可在同一服务接口后替换 |
| 最小后台 | 阶段 5 前置 Supabase 匿名 Auth、Postgres 任务表与私有 Storage、带配额的 API、独立持久工作队列和 worker。阶段 6 再扩展正式账号、跨设备同步、RevenueCat 购买与权益核验 |

端侧流程为原生相机缓冲 → 识别 → 坐标转换与时序匹配 → Flutter 的提示层。原始相片从相机文件直接进入预览。云端流程为用户选片 → 上传确认 → 私有临时对象 → 持久任务 → worker 调用模型 → 私有结果 → 短时授权读取 → 用户另存或删除。服务端密钥留在部署环境；禁止客户端读其他用户任务和文件。[MediaPipe Pose Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker) · [Gemini 图片编辑](https://ai.google.dev/gemini-api/docs/image-generation) · [Gemini 图片理解](https://ai.google.dev/gemini-api/docs/image-understanding) · [Supabase 存储访问控制](https://supabase.com/docs/guides/storage/security/access-control)

### 实时指导、自定义与双人

1. 每帧记录传感器方向、前摄镜像、推理输入缩放、预览裁切。用同一坐标变换处理图像、识别点和用户移动/缩放/旋转/翻转后的目标。分别比较构图偏差与尺度归一化的肢体角度，避免把身高差误报成动作错误。
2. 使用 MediaPipe 的 33 个关键点，选择可见的头、肩、肘、腕、髋、膝、踝；按可见度加权比较关节角和相对方向。置信不足提示“左手未入镜”，避免凭空给分；侧面、遮挡或深度不明确时不推断精确身体旋转角。对齐比例只代表目标匹配，不能声称统计学准确率。多帧稳定后才更新最高优先级的一条提示。
3. 自定义图经端侧 IMAGE 模式推理，保留高置信点、骨长比例和人物分割遮罩，生成独立矢量骨架与轮廓。允许预览并裁定有效区域，保存目标及标签，验证源照片移除后仍能独立叠加和评分。
4. 双人启用最多两个检测目标，使用髋部中心、前一帧位置与尺度做短时关联，首次按画面左右分配 A/B，允许手动交换。重叠或跟踪丢失时暂停相应人物提示；两人独立计分，脸部身份不参与追踪。
5. 拟定真机目标为取景 30 FPS、姿态 8–12 次/秒、动作变化到提示的 P95 延迟 250 ms 内；这是验收目标，尚无测量结果。评分负载过高时优先降识别频率、保留拍照。记录测试机、系统、光线、检测丢失率、发热及连续使用时间。

### 场景和编辑

场景模型输出限定为海滩、楼梯、墙壁、咖啡馆、公园、街道、建筑、座椅、镜子、室内及未知，可多选；推荐器用场景、人数和视角过滤离线目录。暗光、多场景、无合适标签时展示候选并允许纠正。模型分数需校准，避免把语言模型自报的数字直接当作可靠概率。

编辑支持 Golden Hour、Editorial Film、Soft Flash、VHS Camcorder、Vintage、Cinematic、Portrait、Fashion Editorial、Film Photography、Travel Photography 和自定义文字。以原图作为编辑输入，将保留身份、姿势、服装写入约束；对照原图检查脸、手和衣纹。失败可重试，视觉一致性通过样张审核，不能承诺每次完全保真。

自有 API 拟提供创建上传、创建任务、查询状态、取消/删除、读取结果。接口名称在实现时定稿。任务通过幂等键去重，状态为排队、执行、成功、失败、取消；暂时性失败有限次退避。worker 租约到期可恢复，客户端重启按任务 ID 继续查询。为输入、结果设保留期和删除流程；上传前移除不需要的 EXIF 位置信息。无密钥时入口明确显示未配置，禁止以本地滤镜或固定场景冒充 AI。

## 数据设计与权限

| 数据 | 主键或约束、用途 |
| --- | --- |
| users | id 对应 Auth 用户；本机先生成独立 profile，阶段 6 通过明确的合并流程绑定账号 |
| poses、pose_categories、pose_category_members | 稳定 pose_id、版本、人数、素材引用、骨架与主类；多对多标签，公开目录只读 |
| user_favorites、pose_usage | 用户与姿势联合唯一；使用事件按 session_id 去重，聚合使用数与最近时间 |
| custom_poses | owner_id、单/双人、骨架、轮廓引用、来源和版本；默认设备私有，上传需用户触发 |
| photos | 所有者、pose_id、拍摄时间、文件引用、原片/衍生片关系；删除记录与删除系统相册照片分别处理 |
| ai_generations | owner、类型、状态、幂等键、输入/结果引用、尝试次数、错误、保留期限；只有 worker 可写成功与用量 |
| shoot_plans、shoot_plan_items | 地点、主题、顺序、稳定条目 ID、完成状态与照片关联，事务更新进度 |
| subscriptions | 阶段 6，按用户、商店、entitlement 和到期时间存验证快照；Webhook 事件号唯一，客户端无写入权 |

阶段 5 前置后台只部署云 AI 所需子集；其余先按本地仓储接口实现。Supabase 对个人行启用 owner 级 RLS；私有对象短时授权；计费与服务角色密钥仅 worker 持有。正式订阅提议一个 Premium entitlement，关联两家商店实际配置的月/年商品。试用依据商店资格，恢复购买后刷新服务端权益。[RevenueCat 权益模型](https://www.revenuecat.com/docs/getting-started/entitlements)
